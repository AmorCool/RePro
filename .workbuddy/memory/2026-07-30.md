## CI 排障记录（v1.0.0 / v1.0.1 / v1.0.2）

### 拉 CI 日志的可靠办法（RePro 仓库无内嵌 token）
- `gh` 未登录；匿名 API 取 logs 返回 403。
- 可行方式：从 Windows 凭据管理器取 token —
  `printf "protocol=https\nhost=github.com\n\n" | git credential fill` 拿 password，
  再 `curl -H "Authorization: Bearer $TOK" https://api.github.com/repos/<o>/<r>/actions/jobs/<jobid>/logs`
- 先用匿名 `/actions/runs/<id>/jobs` 拿各 step 的 conclusion，定位失败步骤。

### 失败与修复
1. **v1.0.0**：pbxproj 设了 ASSETCATALOG_COMPILER_APPICON_NAME 但无 Asset Catalog → 补 Assets.xcassets。
2. **v1.0.1**：`pod install` 报 `[!] The Podfile does not contain any dependencies.`
   → 项目本无第三方依赖，**直接删除 Podfile + CI 移除 CocoaPods 全部步骤**。
3. **预先排除的必炸点（v1.0.2 一并修）**：
   - **无 shared scheme** → `xcodebuild -scheme RePro` 会报 does not contain a scheme。
     必须提交 `RePro.xcodeproj/xcshareddata/xcschemes/RePro.xcscheme`（BlueprintIdentifier = target ID）。
   - **EESigning.m 含 32 处 C++（ldid::/std::/ldid.hpp）→ 必须重命名 .mm**，
     pbxproj 的 lastKnownFileType 同步改 sourcecode.cpp.objcpp。
   - **clang++ 会把 .c 当 C++ 编译** → libplist/lookup2.c 必炸。
     CI 改为按语言分别编译 .o 再链接（.c=clang -x c / .cpp=clang++ / .m=clang -x objective-c -fobjc-arc / .mm=clang++ -x objective-c++）。
   - **brew openssl@3 是 macOS 版，链不进 iphoneos 二进制** →
     照搬旧项目：交叉编译 openssl-3.4.1 `./Configure ios64-xcrun no-shared no-tests` 到 /tmp/openssl-ios，用 actions/cache 缓存。
   - libplist 的 `#include <config.h>` 被 `#ifdef HAVE_CONFIG_H` 保护，不定义该宏即可，无需提供 config.h。
